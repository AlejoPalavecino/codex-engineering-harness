# Product UX/UI

1. Comprender actores, tareas frecuentes, objetivos, permisos, ambiente de uso y puntos de fricción.
2. Diseñar secuencias de tareas y arquitectura de información antes de definir componentes.
3. Proponer direcciones visuales diferenciadas si hay margen creativo: identidad, jerarquía, tipografía, paleta, espaciado, interacción y consistencia.
4. Cubrir errores, validación, confirmaciones, loading/empty/success/denied, navegación, teclado, foco, contraste y dispositivos pertinentes.
5. Presentar flujos/pantallas y decisiones principales para aprobación **antes** de implementar interfaces sustanciales.
6. Validar con navegador o herramienta apropiada si está instalada/autorizada; usar datos de prueba, revisar responsive e interacción real.
7. Documentar criterios UX/UI verificables, no solamente adjetivos como «moderno» o «lindo».

La originalidad no justifica sacrificar claridad ni accesibilidad.
