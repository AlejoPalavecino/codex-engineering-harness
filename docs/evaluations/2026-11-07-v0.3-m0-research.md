# Chuli v0.3 — Investigación M0

**Fecha:** 2026-11-07  
**Baseline:** main, commit 7c15a83 (v0.2.1 integrado).  
**Estado:** investigación documental completada; pruebas de backend local pendientes.

## Resumen

Codex ya ofrece perfiles nativos de permisos, un comando estable para probes y soporte de configuración por perfil. La solución recomendada combina Permission Profiles, CODEX_HOME aislado, procesos principales separados, Git Worktrees y verificación independiente. No se recomienda construir un sandbox propio.

## Hallazgos

1. Permission Profiles son beta, están documentados para Windows, Linux, WSL y macOS, y requieren Codex CLI 0.138.0 o posterior. La release más reciente observada es 0.167.0 (2026-11-06). Fuente: https://learn.chatgpt.com/docs/permissions y https://github.com/openai/codex/releases/tag/rust-v0.167.0
2. Los perfiles integrados son :read-only, :workspace y :danger-full-access. Chuli solo utilizará :read-only y :workspace, más perfiles propios. Fuente: https://learn.chatgpt.com/docs/permissions
3. Permission Profiles no componen con sandbox_mode / sandbox_workspace_write. Si sandbox_mode aparece en una capa cargada o se pasa --sandbox, Codex usa el sistema heredado. Fuente: https://learn.chatgpt.com/docs/permissions
4. CODEX_HOME contiene configuración, autenticación, sesiones, logs y skills. --profile nombre carga CODEX_HOME/nombre.config.toml. Fuente: https://learn.chatgpt.com/docs/developer-commands?surface=cli
5. codex sandbox ejecuta probes bajo las políticas locales de Codex. Fuente: https://learn.chatgpt.com/docs/developer-commands?surface=cli
6. Los subagentes heredan sandbox, approval policy, permisos y MCP del proceso padre. Un agente TOML no puede reemplazarlos. Fuente: https://learn.chatgpt.com/docs/agent-configuration/subagents
7. Git Worktrees separa árboles de archivos pero comparte metadata Git; no es frontera de seguridad. Fuente: https://learn.chatgpt.com/docs/environments/git-worktrees
8. macOS utiliza Seatbelt; Linux/WSL bubblewrap + seccomp; Windows puede utilizar MXC o elevated. Unelevated no admite deny-read y tiene limitaciones de red. Fuentes: https://learn.chatgpt.com/docs/sandboxing y https://learn.chatgpt.com/docs/windows/windows-sandbox
9. network.enabled no inicia el proxy. Para reglas de dominio se requiere features.network_proxy=true. MCP, búsqueda web, conectores, browser, Computer Use y servicios cloud son superficies separadas. Fuente: https://learn.chatgpt.com/docs/permissions
10. apply_patch consulta la política efectiva de filesystem y calcula permisos adicionales para rutas no escribibles. Por eso se debe probar en una sesión real. Fuente: https://github.com/openai/codex/blob/main/codex-rs/core/src/tools/handlers/apply_patch.rs

## Recomendación

- CODEX_HOME de Chuli separado en ~/.chuli/codex-home; no copiar auth.json, tokens ni MCP personales. El usuario inicia sesión una vez.
- Un proceso principal por etapa/perfil; los subagentes comparten el perfil del padre.
- Git Worktrees administrados por Chuli; .git fuera de la escritura de agentes.
- Tests aprobados congelados por commit y hash; implementation tiene read sobre ellos.
- Reviewer read-only; verifier sobre una copia temporal descartable.
- Red local deshabilitada y cero MCP por defecto.
- Windows como primera plataforma de aceptación; MXC o elevated solo si pasan probes. Unelevated bloqueado para perfiles con deny-read.
- Linux/macOS solo se declaran soportados tras sus probes reales.

## Límites no verificados

Esta investigación es documental. No se ha probado en el equipo del usuario:
- versión de Codex CLI, build de Windows y backend efectivo;
- disponibilidad de MXC/elevated;
- denegación de apply_patch sobre tests congelados;
- comportamiento de procesos hijos y enlaces;
- proxy de red, configuración administrada y MCP.

Estos puntos se convierten en pruebas M0/M4. No se declara todavía aislamiento efectivo.
