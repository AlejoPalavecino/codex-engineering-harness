# Chuli v2.1.7 · Resiliencia ante límite de consultas de GitHub API

Esta release corrige el error `GitHub Releases: HTTP 403` cuando se agota el límite anónimo de `api.github.com` (60 pedidos por hora por IP), sin cambiar roles, modelos, permisos ni manifiestos:

- **Fallback sin límite de API en `Latest()`:** ante `HTTP 403` o `429` por rate limit de `api.github.com`, Chuli Manager resuelve el tag siguiendo de forma segura la redirección `https://github.com/AlejoPalavecino/codex-engineering-harness/releases/latest`, rechazando destinos fuera de `github.com` o tags inválidos.
- **Resolución única en instalaciones multi-plataforma:** el asistente TUI resuelve la última versión una sola vez antes de iterar por `Codex`, `Claude Code` y `AGY CLI`, evitando consultas redundantes y aprovechando la caché local verificada.
- **Soporte opcional de token y mensajes claros:** si `GITHUB_TOKEN` o `GH_TOKEN` está definido en el entorno, se envía únicamente a `https://api.github.com` (nunca hacia redirecciones web); si ambos caminos fallan, muestra la hora de reinicio del límite y la opción de configurar token.
- **Trazabilidad:** cambios y pruebas unitarias en `internal/manager/releases.go`, `internal/manager/releases_rate_limit_test.go`, `internal/tui/wizard.go` y tablero `odd/tasks/github-rate-limit-fallback.md`.

Para actualizar el perfil desde v2.1.6, ejecutá `chuli --client <codex|claude|agy> update`, revisá el plan y repetí con `--apply`. Para actualizar el binario Manager, usá `go install github.com/AlejoPalavecino/codex-engineering-harness/v2/cmd/chuli@v2.1.7` o descargá los archivos de esta release verificando `SHA256SUMS.txt`. Para volver atrás en un perfil, revisá `chuli rollback` antes de aplicarlo.
