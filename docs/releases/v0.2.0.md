# Chuli v0.2.0 — Evaluación y recursos TTP

Publicación e integración autorizadas por el responsable del proyecto el 2026-11-05.

## Novedades

- Evaluación reproducible con 11 escenarios, criterios críticos, fixtures sintéticos, snapshots SHA-256 y reportes CLI.
- Preflight offline de procedencia, permisos efectivos, probes y eventos. Distingue READY, BLOCKED y NOT_VERIFIABLE sin ejecutar modelos ni autenticar las evidencias declaradas.
- Plantilla y guía TTP instaladas junto a `taskboard.py` bajo `CODEX_HOME/harness`, con instrucciones para generar y validar tableros canónicos.
- Recursos administrados por el mismo manifiesto, hashes, preservación de personalizaciones, backup y rollback existentes.
- Corrección de compatibilidad de `verify.ps1` con Windows PowerShell 5.1 y regresión del paquete TTP en PowerShell 5.1 y 7.
- Formulario de issues, catálogo de etiquetas y plantilla de PR para revisión trazable.

Se conservan el Manager TUI, los modelos, los estados y el formato TTP. Los reportes y el catálogo conservan su referencia histórica inmutable a v0.1.3.

## Evidencia y límites

La candidata funcional pasó 32 tests Python, estructura del repositorio, pruebas Go, instalación/rollback Windows y revisión independiente. La integración y los artefactos se verifican nuevamente antes de publicar.

- [Resultados de las seis OPT](../evaluations/2026-11-04-opt-execution.md).
- [Distribución y generación real TTP](../evaluations/2026-11-05-ttp-resources.md): una sesión generó un tablero canónico final con autocorrección del agente; las comprobaciones R0/R1 mantuvieron proporcionalidad.
- El preflight no autentica fuentes ni equivale a un permiso efectivo. Un check TTP solo verifica estructura; las pruebas declaradas necesitan evidencia independiente.
- Las muestras corresponden a Codex CLI en Windows. No certifican Desktop, éxito universal, ahorro de tokens ni aislamiento global.
- Hay binarios Windows x64, Linux x64 y macOS arm64; la instalación y el rollback siguen habilitados y probados solo en Windows. No se afirma ejecución nativa de los binarios Linux/macOS a partir de su compilación.

## Distribución y actualización

Los tres archivos comprimidos incluyen el ejecutable `chuli` de la plataforma; `SHA256SUMS.txt` permite comprobar integridad. Se construyen desde el commit exacto de `main` que pasó CI. No tienen firma criptográfica.

En Windows, descargá `chuli_v0.2.0_windows_amd64.zip`, verificá su SHA-256 y extraé `chuli.exe`. La instalación del harness desde la release conserva vista previa y confirmación; no autoactualiza el propio binario. Requiere Git, PowerShell y Python 3.11+ para instalar.

Antes de reemplazar personalizaciones, revisá el plan. `-ReplaceCustomized` es explícito y crea backups. El rollback existente usa su manifiesto, restaura originales y rechaza deriva antes de mutar. Para volver al ejecutable anterior podés conservar v0.1.3; no se mueve ni reemplaza su tag.
