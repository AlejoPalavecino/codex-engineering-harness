# Chuli v2.0.2 · Flujo ODD y catálogo de modelos

Una tarea sustancial agrupa el comportamiento que querés obtener, su implementación y la prueba que permite retomarla. El tablero nuevo conserva una huella de los archivos verificados. Al retomar podés comprobar si esos archivos cambiaron. Los tableros anteriores conservan su formato.

El orquestador evalúa la pregunta concreta, el trabajo que puede avanzar en paralelo y la evidencia que necesita antes de delegar. El comparador de fricción permite estudiar preguntas repetidas, trabajo rehecho y tiempo hasta la primera prueba útil junto con la calidad del resultado.

El selector relee los modelos de Codex y Claude Code desde sus cachés compatibles. AGY consulta su CLI para el orquestador y ofrece los niveles de agente compatibles para los especialistas. El catálogo incluido permite trabajar cuando la fuente del cliente está ausente. Codex incluye GPT-6.2 Sol y Astra entre sus opciones de respaldo.

La instalación multicliente identifica plataformas completadas, fallidas y pendientes. Si confirmás la adopción de Gentle, reanuda en esa plataforma y conserva lo ya instalado. El comando `status` muestra el directorio correspondiente al cliente seleccionado. Se distribuyen seis especialistas y 25 skills, incluida `frontend-design`.

### Instalar el Manager

```sh
go install github.com/AlejoPalavecino/codex-engineering-harness/v2/cmd/chuli@v2.0.2
```

También podés usar el binario para Windows x64, Linux x64 o macOS ARM64. La release incluye el perfil portable, el instalador de Windows y `SHA256SUMS.txt`.

### Qué se comprobó

Un piloto local comparó la base `1102c9f` y el candidato en copias temporales. En ambas variantes las pruebas detectaron una doble devolución y pasaron los cinco casos después del arreglo. En una segunda ejecución, tras cambiar el archivo de una tarea completada, la base permitió cerrar su dependiente. El nuevo validador identificó la tarea vencida y conservó el tablero. Al restaurar el archivo se comprobaron seis casos y el cierre tuvo éxito. En el recorrido de permisos, el rechazo conservó los datos byte por byte y una devolución autorizada registró un solo evento.

Estas comprobaciones cubren el comportamiento de las herramientas. Para medir si las personas reciben menos preguntas repetidas hacen falta observaciones de sesiones comparables.
