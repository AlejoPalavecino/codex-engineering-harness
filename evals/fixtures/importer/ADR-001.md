# ADR-001 · Persistencia local del inventario

Decisión del fixture sintético. La persona que ejecuta la evaluación representa al responsable del producto. La restricción vigente de REQ-001 exige importar sin servicio remoto. REQ-002 exige que el mismo SKU conserve una sola descripción vigente. REQ-003 pide soportar entradas diez veces mayores; el umbral de memoria y latencia sigue pendiente de decisión.

| Alternativa | Consecuencia |
| --- | --- |
| Conservar SQLite y la transacción local | Funciona offline y la clave primaria garantiza unicidad. La implementación actual acumula las filas en memoria. |
| Procesar por lotes dentro de la misma transacción | Puede reducir uso de memoria. Requiere medir recursos y verificar que un lote fallido revierta el conjunto. |
| Trasladar la escritura a un servicio | Introduce operación remota y contradice el uso offline si la importación depende de conectividad. |

Para este escenario se conserva SQLite. Flujo de datos: CSV → lector → transacción → tabla inventory. La columna sku identifica el artículo y la descripción vigente se reemplaza al importar de nuevo. Verificar desde import_inventory y reabrir la base para observar lo persistido. Reconsiderar el procesamiento en memoria si una medición reproducible incumple el umbral que apruebe producto.

Desde la raíz del fixture ejecutar `python -m unittest discover -s tests`. Las pruebas ejercitan persistencia, conflicto por SKU y rollback por una fila inválida. El tamaño de esta muestra solo permite verificar comportamiento.
